# miniQMT 收紧：别打听名单，自己验证三步

「哪家券商不给 miniQMT」这个问题没有稳定答案 —— **不是没人统计，是它在变**。列名单会过期，反而误导。

## 先分清你遇到的是哪一种「收紧」

1. **新开被拒** —— 以前能申请，现在提交不批。影响的是还没上车的。
2. **已开通被降级** —— 已开通的客户端被换成只有自带编辑器的那种，外部调用能力没了。影响的是已经跑起来的。
3. **通道层面不统一** —— 同一个券商，A 营业部给、B 营业部不给。这种最坑，因为「我朋友能用」和「我不能用」可以同时成立。

## 最小验证三步

1. **看客户端里有没有对外服务的模块。** 有，说明本机调用这条路还在。
2. **用最小脚本连一次。** 只要能连上并取到一次行情，这条路就是通的。
3. **问营业部时问「当前」、问通道。** 别问「你们家支不支持」。

## 被收紧了，原来写的脚本还能不能用

先分清你缺的是**「本机调不通接口」**还是**「策略想继续留在原来的平台上」** —— 这两个问题的解法完全不同，选错会白折腾一两周。

如果只是要外部 Python 查行情、对持仓，那就算只给你自带编辑器的那种客户端，也可以在客户端里起一个**只听本机**的 HTTP 接口，让外部脚本通过它取数。

⚠️ 有个必踩的坑提前说：客户端内置的 Python 自带 tornado，不用额外装框架，但**必须把服务丢到后台线程**。如果在初始化函数里直接启动事件循环，会占住线程导致主循环不再执行。

完整写法：https://www.kimiquant.cn/problems/qmt-local-http-bridge
