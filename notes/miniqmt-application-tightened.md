# miniQMT 收紧：怎么验证自己现在还能不能用

「哪家券商不给 miniQMT」这个问题没有稳定答案——**不是没人统计，是它在变**。列名单会过期，反而误导。所以这里只讲怎么自己验证。

## 一、先分清你遇到的是哪一种「收紧」

「收紧」不是一个单一状态，至少有三层，影响完全不同：

1. **新开被拒**——以前能申请，现在提交不批。影响的是还没上车的。
2. **已开通被降级**——已开通的客户端被换成只有自带编辑器的那种，外部调用能力没了。影响的是已经跑起来的。
3. **通道层面不统一**——同一个券商，A 营业部给、B 营业部不给。这种最坑，因为「我朋友能用」和「我不能用」可以同时成立。

先把这三层分清楚，再去问才有意义。

## 二、为什么名单不可靠

miniQMT 本质上是把客户端函数能力**开放给本机的外部程序调用**。这个「对外开放」的口子属于外接类能力，各家在监管口径下的处理方式一直在调整。

结果就是同一个券商不同通道给的不一样；有的以前给、现在新开收紧；有的不给 miniQMT 但能用别的方式达到类似效果。

网上任何一份名单，都只代表**写那份名单的时刻**。

## 三、最小验证三步

不要靠打听，靠验证：

1. **看客户端里有没有对外服务的模块**。有，说明本机调用这条路还在；没有，就只剩客户端自带编辑器了。
2. **用最小脚本连一次**。只要能连上并取到一次行情，这条路就是通的；连不上，再排查是环境问题还是权限问题。
3. **问营业部时问「当前」**。一定要加时间限定词，而且要问通道，不要问「你们家支不支持」。

这三步做完，拿到的信息比任何名单都准。

## 四、被收紧了，原来写的脚本还能不能用

关键要先分清你缺的是哪一样：**是「本机调不通接口」，还是「策略想继续留在原来的平台上」**。这两个问题的解法完全不同，选错会白折腾一两周。

如果只是要外部 Python 查行情、对持仓，那就算只给你自带编辑器的那种客户端，也可以在客户端里起一个**只听本机的 HTTP 接口**，让外部脚本通过它取数。

⚠️ 有个必踩的坑提前说：客户端内置的 Python 自带 tornado，不用额外装框架，但**必须把服务丢到后台线程**。如果在初始化函数里直接启动事件循环，会占住线程导致主循环不再执行。

完整写法与可跑示例：https://www.kimiquant.cn/problems/qmt-local-http-bridge

开源桥方案（已有成套 `xtquant` 写法、想少改代码）：https://www.kimiquant.cn/notes/cfquant-miniqmt-bridge

## 五、顺序别搞反

1. 先定**你要做什么**（取数研究，还是自动下单）
2. 再看**有没有不需要特定权限的替代路径**
3. 最后才去问券商**当前**能给你什么

倒过来——先纠结「哪家给 miniQMT」再想用途——很容易开通完才发现，你要走的那条路根本不需要它。
